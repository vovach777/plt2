# palic-2-js

Текстовый вид [palic-2](../palic-2). Это не бинарный файл. Раскладка та же: тайл 288, `off = 2`, `L` считается по символам сверху и не пишется, RCT, MED, `wrap8` у Y и `wrap9` у U/V, зигзаг, блоки по 16 символов через строку. У плоскости восемь корзин `L0..L7` и маски. Символ 511 при `L = 0` у хромы — обычный символ алфавита 512.

Node.js 18+, зависимостей нет.

```bash
node pln-text.js
```

Печатает `PLN2-TXT` синтетики 8×8 (`R = x·32`, `G = y·32`, `B = 128`) и проверяет, что декодер возвращает те же числа.

Из кода: `renderTxt(rgb, w, h)` и `renderGrayTxt(gray, w, h)` пишут `PLN2-TXT` / `PLN1-TXT`. `parseTxt` читает этот текст обратно. Энтропия сюда не входит.

## PLN2-TXT

```text
PLN2-TXT
W H
4 13 22
L0 -
L1 11 14
M 20
```

Строка 1 — имя, строка 2 — размер картинки. Дальше индекс: номера строк, где в этом файле начинаются Y, U и V, через пробел. У серого `PLN1-TXT` в индексе один номер, не три. Тайлы одного ряда картинки стоят на одной строке индекса и разделены табом. Размер тайла из сетки, в файл не пишется:

```text
nx = (W + 287) / 288
ny = (H + 287) / 288
```

Потом плоскости по порядку Y, U, V. У каждой восемь строк `L0`…`L7` и строка `M`. В `PLN-TXT` там прогоны (`11` — один символ 1, `F` — выход в varint), не сырые десятичные числа. Пусто — `-`.

## Энтропия

[entropy.js](entropy.js) берёт `PLN-TXT` и отдаёт байты. Обратно `decompress` возвращает тот же текст: числа достаёт из бинаря, а строки снова рисует текстовый кодек.

```js
const { compress, decompress } = require('./entropy');
const bytes = compress(text, 'rice');   // или 'runlen'
decompress(bytes) === text
```

`RC02` / `RC01` — Rice, `k` это `floor(log2)` среднего последних трёх символов. `RL02` / `RL01` — ниблы: два символа `0..E` в байте, `F0` и два нибла — прогон нулей от 4, `F1` и четыре нибла — символ больше 14.

Эталон того же входа — `bzip2 -9` этого `PLN-TXT`. palic-2 в рейтинге для сравнения, он жмёт пиксели, не текст. Место считается по цвету.
