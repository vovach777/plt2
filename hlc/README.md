# hlc — HALIC-класс на базе PALIC-1

Один цветовой трансформ (наш RCT = режим 0 HALIC), независимые тайлы 256×256, только MED (без ветвлений, как у
HALIC); энкодер пишет остатки на место плоскости, обходя тайл с конца (соседи ещё исходные), SSE4.1 по 8; полный zigzag-алфавит, одна таблица FSE на плоскость-тайл,
все три плоскости — один и тот же FSE4 (u16-символы, см. ниже). Декодер как у HALIC: FSE пишет прямо в буфер тайла, предиктор
восстанавливает плоскость на месте, обратный RCT — SSSE3 по 16 пикселей сразу в RGB. Тайлы независимы → `-t N` потоков.

```
hlc c in.ppm out.hlc [-t N] [-n]     hlc d in.hlc out.ppm [-t N]     hlc bench [-t N] [-n] a.ppm ...   # -n: без энтропийного кода
```

|---|---|---|

## `-s`: косые полосы по 8 строк (волновой фронт MED, 8 лейнов SSE)
Пиксель (x, k) полосы лежит по адресу (x + k)·8 + k, вектор t — антидиагональ (t−k, k). Соседи MED: a = V(t−1),
b = V(t−1) со сдвигом на лейн (лейн 0 — строка над полосой), c = b прошлого шага; края — виртуальные нули, это ровно
растровые правила. MED тот же самый (поток бит в бит восстанавливается), меняется только порядок остатков.
Выход в растр — транспонирование 8×8 int16.

|---|---|---|
| `-n` растр (только остатки) | 48.00 | 560 / 428 |
| **`-n -s` косые полосы, декодер слитный (MED → транспонирование → обратный RCT сразу в RGB), края полос — загрузки по маске** | **48.00** | ~480 / **~1400–1460** |
| FSE, растр | 4.9188 | 260 / 221 |
| **FSE, `-s`** | **4.9190** | 242 / **~360** |

В потоке только настоящие пиксели: треугольники полос не хранятся, декодер добивает их нулями сам
(середина полосы — одна загрузка 8 остатков, края — короткие куски).

Слитный декодер `-s`: около 8 инструкций на отсчёт (callgrind), без промежуточных растровых плоскостей.

## FSE4: tANS по u16, 4 состояния (формат HLC3)
Библиотечный `FSE_decompressU16` — одно состояние, reload на каждый символ и запись таблицы на битовых полях
(у MSVC `{u16; unsigned:4; unsigned:12}` вообще 8 байт). Свой кодек поверх библиотечных NCount / normalizeCount /
CTable: 4 чередующихся состояния в одном битовом потоке (символ i — состояние i mod 4), reload раз на 4 символа
(4 × tableLog 12 ≤ 56 бит), своя плоская таблица u32 `newState | nbBits<<16 | symbol<<20`, вывод сразу в int16 тайла.
FSE8, сужение/расширение u8 и escape больше не нужны. `-T` — максимум tableLog (по умолчанию 12).

## HLC4: ленты + развязанные блоки статистики (формат по умолчанию)
Тайл нёс две роли: регион статистики FSE и буфер волны MED. Теперь они разведены:
- **лента** — R строк × вся ширина: волна MED идёт непрерывно по полосам 8 строк через всю ширину, предсказание
  сбрасывается только на верхней границе ленты; ленты независимы (`-t N`);
- **блок статистики** — шаги волны t ∈ [jB, (j+1)B) всех полос ленты (параллелограмм со скосом 7 px): декодер читает
  из потока блока непрерывные векторы по 8, без склейки на стыках; MED на стыках блоков видит настоящих соседей.
- FSE4-декодер возобновляемый (состояния и битовый ридер живут между сегментами), tableLog ≤ ⌊log2 n⌋ − 4
  (таблица ≤ n/16 записей, `-Ta 0` выключает).
- `-B` (128), `-R` (128), `-dord 1` — сначала каждый поток целиком в буфер ленты (таблица горячая в L1);
  `-dord 0` — по полосам (буфер полосы в L1, но таблицы блоков вытесняют друг друга — медленнее).
- `-L -s` — прежний HLC3 с тайлами; `hlc est -tw B -th R` — оценка размера без декодера.

Цена HLC4 — около −4% к декоду (≈ +3% инструкций: больше потоков, учёт сегментов, буфер ленты).

## Режим потока 7: три плоскости тайла в одном битовом потоке
Порядок символов Y_i U_i V_i Y_i+1 …, K состояний на плоскость (`-K`, по умолчанию 2), у каждой плоскости своя таблица
(tableLog ≤ 12), один битовый ридер, перезагрузка раз на 4 символа. Символы идут в порядке, нужном волне. `-J 0` —
прежние три потока (`-d3 1` — их декод вперемешку, `-d3 0` — по очереди).

| 1 поток, VM, медиана 6 прогонов | кот dec MB/s | 14 картинок dec MB/s |
|---|---|---|
| три потока по очереди | 561 | 573 |
| три потока вперемешку (12 цепочек, 3 ридера) | 587 | 598 |
| **один поток, K = 2 (6 цепочек, 1 ридер)** | **589** | **596** |
| один поток, K = 1 (3 цепочки) | ~443 | ~454 |

K = 1 упирается в задержку цепочек; 6 цепочек хватает. Размер −0.03% (один поток вместо трёх).

## Выбор предиктора на плоскость тайла (как у HALIC)
Четыре режима HALIC: 0 MED, 1 trunc((2(a+b)−c)/3), 2 (a+b+1)>>1, 3 без предсказания; на тайл байт режимов
(2 бита на плоскость V, U, Y; флаг 2 в заголовке). Выбор — argmin энтропии нулевого порядка zigzag-остатков
(у HALIC — энтропия 256-бинной гистограммы 8-битной разности, без гистерезиса), оценка по каждой 8-й строке (`-Ps`).
Режим действует внутри тайла; строка 0 и столбец 0 всегда предсказываются левым/верхним соседом (иначе /3 с
нулевыми соседями даёт 2a/3 и портит выбор). В волне это маска `blendv` на лейнах края (треугольник полосы,
лейн 0 первой полосы); середина полос — чистый шаблон режима. `/3` в SIMD: mulhi(x, 21846) − (x >> 15) = trunc(x/3)
(проверено на всём диапазоне |x| ≤ 1275). `-P mask` — разрешённые режимы.

## Межхроматическое предсказание остатков (ветка `xres`)
V = R−G и U = B−G содержат общий −G, поэтому их MED-остатки коррелируют (+0.2…0.3). На тайл: направление (U по V или
V по U) и k ∈ [−8, 8]: e_t′ = wrap9(e_t − ((k·e_s + 4) >> 3)). Работает по zigzag-потокам в skew-порядке (тот же индекс —
тот же пиксель); декодер возвращает поправку одним SIMD-проходом перед волной (~14 операций на 8 сэмплов).
Байт на тайл (флаг 3). Выбор: устойчивая регрессия (только |e| ≤ 8, `-Xc`) даёт стартовое k, затем спуск по
энтропии пробы (каждый 11-й сэмпл, `-Xs`) — совпадает с полным перебором (`-Xf 1`). `-X 0` выключает.

| **с поправкой** | **5.6225 (−2.41%)** | **4.5500 (−2.61%)** | 260 | ~560 |

## HLC5 (experiment, branch ctx5): whole-image skew + activity contexts (`-5`)

No tiles: MED wave over 8-row bands across the full width. Each sample gets a class from its causal
neighbourhood, act = |a-c| + |c-b| + |a-aa| (aa = two to the left; pctx's up-right d is not decoded yet in a
wave step), thresholds as pctx (Y 1 3 10 18 35, U/V 1 4 8 16 30). 11 streams: class 0 shared by all planes,
classes 1..5 of Y, classes 1..5 of U/V. Symbol order = decoder order (band, step, plane V U Y, lane).
FSE per chunk of `-cb N` symbols of a stream (0 = one table per stream). Decoder: all streams FSE-decoded into
one buffer, then one wave pass with the three planes interleaved per step; class in SIMD, gather per lane
(fast path: all 8 lanes one class = one 16-byte load). `-n` = raw streams (cost of the separation alone).
`-g5 0|1|2`: serial gather / rank gather / debug (always fast path, wrong output, timing only).

16 photos (JPEG 4:2:0, downscaled 2x -> 4:4:4), sandbox: HALIC 8.6530 bpp; HLC3 MED only 8.6974;
HLC5 -cb 65536 8.1954 (-5.3 % vs HALIC), dec 418 MB/s (HLC3 613), raw dec 733 (HLC3 raw 1800).
The step chain V(t-1) -> class -> address -> Z -> MED -> V(t) is the cost; classes from t-2 data only
(c, aa, (y-1,x-2), (y-2,x)) would cut it to MED, entropy estimate -8.55 % instead of -10.13 % vs no contexts.
xres (cross-chroma, HLC3) is now off by default: `-X 1`.
