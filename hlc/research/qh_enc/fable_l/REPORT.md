# Screen-блоки в PLR: правило хвоста, screen-режим с пониженным L, переключатель на тайл

Claude Fable subagent, оценки на дампах (prototype в кодеке не делался). Cost model = qhsim (реальные длины Huffman <= 11,
хвосты, 16 L planes) + runs + zU split, как exp_pred. Screen-таблицы held-out: обучение на 12 экранах вне тестовых
(/tmp/sc/gb82sc/{codec_wiki,gmessages,graph,gui}, /tmp/sc/qoiweb/{amazon,apple,cnn,creativecommons,imdb,microsoft,nytimes,reddit}),
тест на 12 из halic-wins-screen-p6 (все 12, включая phoboslab) и на CLIC test 39 colour + 39 gray.
Скрипты: lspike.py (раунд 1), lspike2.py (раунд 2), summ.py / summ2.py; полные таблицы: round1.txt, round2.txt.

## Варианты
1. Правило хвоста (T, g): q = x >> k; q < T: Rice как сейчас; иначе T единиц + Exp-Golomb порядка g от x - (T << k)
   (сейчас: 24 единицы + 10 raw). Side info нет, это просто другой escape.
2. Screen-режим S: свои 32 таблицы (Rice k до 4), L = clamp(bw(est >> 4) - 2 - d, 0, 7), est = сумма сверху (A),
   max / min / среднее (сверху, предыдущий блок); контекст Q(est) либо 2-D (bw(sa), bw(sl)).
3. Переключатель: 1 бит на тайл (фото-таблицы формата / screen-режим), оракул по стоимости тайла.

## Выводы
- Правило хвоста (6,1) или (8,2): -7% на экранах, CLIC не хуже (-0.03…-0.07%), без side info. Берётся отдельно.
- В screen-режиме главный рычаг — не «свой L», а L на 3 ниже причинного (фактически off 5) + переобученные
  таблицы с Rice k до 4: d=0 -14.4% -> d=3 -22.3%. L=0 всегда (аналог классов PALIC-1) хуже, чем d=3.
- est = max(сверху, предыдущий блок) даёт ещё ~1.2 п.п.; min хуже; 2-D контекст +0.6 п.п.
- Цена формата: 1 бит на тайл; вторые 32 таблицы (ещё 128 KB lookup в decoder'е); encoder'у нужен выбор на тайл
  (оценка двух сумм длин кодов, либо один флаг на файл).
Не мерил: свой L поверх d=3; отдельная маска outlier'ов (L=0 + EG хвосты её приближает и проигрывает d=3);
переобучение Rice k фото-таблиц под новое правило хвоста; phoboslab вошёл в тест (памяти хватило).
